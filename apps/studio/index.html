AC

Users, Login, and Access

CGA is an operating system for bot production, so user identity and permission boundaries are part of the Public Core.

Maps to Public Core: login state / roles / scopes / audit-ready actions

Login

Authenticated users can create, configure, review, deploy, or operate bots based on role.

Roles

Owner, Admin, Builder, Reviewer, Operator, and Viewer roles separate responsibilities.

Permission Scopes

Create, configure, review, deploy, user management, and API answer management scopes are explicit.

Access Operations Snapshot

The operator should see group, user, approval, and language status without opening a database or command line.

Login Session

Switch the active user and immediately recalculate group memberships, screen access, and user language.

Signup

A new user receives a personal group and becomes that group’s administrator.

Group Management

Create groups and request membership using the current user session.

Approval Queue

Group join requests are approved by the target group administrator. Admin permission requests are approved by system admin.

Signup / Login Flow

The first access path is explicit: sign up, receive a personal group, log in, then request access to another group when needed.

Group Users

A group owns bots and APIs. Users receive roles inside the group, and those roles decide screen access.

Group Join Requests

Users can request access to another group. Approval creates a membership for that group.

Admin Permission Requests

Admin permission requests are visible to the system admin and must be approved before privilege changes.

Group Bot Access

Bots and APIs are managed by group. Users in the same group can access the group bot according to group scopes and their role.

Current User Screen Access

Screens and actions are resolved from group membership, group scopes, role scopes, and user overrides.

Signup and Group Policy

Every new user signs up into their own group first. Users can request to join another group, and empty groups are deleted automatically.

Admin Approval Policy

The base admin user cannot be deleted. Group creation and admin permission requests require approval by the system admin.
