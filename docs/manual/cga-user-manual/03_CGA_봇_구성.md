# CGA Studio 사용자 매뉴얼

## 3장. 봇 구성

### 3.1 문서 목적

이 문서는 `봇 설정` 다음 단계인 `봇 구성` 화면을 설명합니다.  
이 문서를 따라하면 사용자는 학습문장을 입력하고, 의도 후보를 확인하고, 현재 버전에 후보를 반영하는 기본 흐름을 이해할 수 있습니다.

### 3.2 사용 대상

- `01_CGA_처음부터_봇_생성까지`를 완료한 사용자
- `02_CGA_봇_설정`에서 기본 설정을 확인한 사용자
- 실제 대화 구성을 시작하려는 사용자

### 3.3 문서 범위

이 문서에서는 아래를 다룹니다.

- `03 봇 구성` 화면 진입
- 학습문장 입력 영역 이해
- 의도 후보 생성 구조 이해
- 후보 검토와 현재 버전 반영 흐름 이해

이 문서에서는 아직 다루지 않습니다.

- 세부 대화 카드 설계
- 개체/사전 고급 조정
- 운영 배포

## 4장. 봇 구성의 역할

`봇 구성`은 사용자가 넣은 학습문장이나 자료를 바탕으로 의도 후보를 만들고 검토하는 단계입니다.

핵심 목표:

1. 질문 예시를 넣는다.
2. 시스템이 후보 의도를 정리한다.
3. 사용자는 후보를 검토한다.
4. 검토 결과를 현재 버전에 반영한다.

노트:

- 이 단계는 “대화를 완성하는 단계”가 아니라 “의도 초안을 만드는 단계”에 가깝습니다.

## 5장. 봇 구성 화면 열기

### 5.1 워크플로우에서 열기

1. 좌측 워크플로우 메뉴에서 **03 봇 구성**을 클릭하세요.
2. 화면 제목이 **봇 구성**으로 표시되는지 확인하세요.
3. 부제목이 학습문장 기반 의도 후보 생성 의미로 보이는지 확인하세요.

### 5.2 봇 작업공간에서 열기

1. **봇 작업공간**에서 현재 작업 봇을 선택하세요.
2. **봇 구성 열기**를 클릭하세요.

## 6장. 화면 구성 이해

`봇 구성` 화면은 보통 아래 두 영역으로 이해하면 됩니다.

| 영역 | 역할 |
| --- | --- |
| 입력 작업 영역 | 학습문장 또는 입력 자료를 넣는 영역 |
| 후보 검토 영역 | 생성된 의도 후보를 검토하는 영역 |

사용자 관점에서 가장 중요한 것은 아래 두 가지입니다.

1. 무엇을 넣어야 후보가 만들어지는가
2. 만들어진 후보를 어디서 검토하고 반영하는가

## 7장. 학습문장 입력하기

### 7.1 학습문장의 의미

학습문장은 사용자가 실제로 할 만한 질문 예시입니다.

예시:

- 배송 상태를 알려주세요
- 주문 취소하고 싶어요
- 환불은 어떻게 하나요
- 비밀번호를 변경하고 싶습니다

### 7.2 입력 절차

1. 학습문장 입력 영역을 찾습니다.
2. 한 줄에 하나씩 질문 예시를 입력합니다.
3. 입력 내용이 실제 사용자 표현과 비슷한지 확인합니다.

### 7.3 작성 원칙

처음 사용자는 아래 원칙만 지키면 충분합니다.

1. 실제 사용자가 말할 문장으로 작성합니다.
2. 한 의도에 너무 많은 의미를 섞지 않습니다.
3. 비슷한 질문은 여러 표현으로 넣어도 됩니다.

좋은 예:

- 배송 조회하고 싶어요
- 제 택배가 어디쯤 왔나요
- 배송 상태 확인해줘

좋지 않은 예:

- 배송도 보고 싶고 취소도 하고 싶고 환불도 알고 싶어요

## 8장. 의도 후보 확인하기

### 8.1 의도 후보의 의미

의도 후보는 입력한 학습문장을 기준으로 시스템이 나누어 본 대화 주제 초안입니다.

예를 들면 아래와 같은 후보가 생길 수 있습니다.

- 배송 조회
- 주문 취소
- 환불 문의

### 8.2 확인 절차

1. 후보 영역에서 목록 또는 테이블이 보이는지 확인하세요.
2. 후보별 이름, 문장 수, 상태 같은 정보가 보이는지 확인하세요.
3. 어떤 후보가 어떤 질문을 대표하는지 눈으로 검토하세요.

### 8.3 처음 사용자 권장 확인 포인트

1. 후보가 너무 넓게 묶이지 않았는지
2. 서로 다른 의미가 하나로 섞이지 않았는지
3. 같은 의미 후보가 중복으로 쪼개지지 않았는지

## 9장. 후보 검토하기

### 9.1 검토의 목적

후보 검토는 자동으로 만들어진 의도 초안을 사람이 확인하는 단계입니다.

### 9.2 검토 절차

1. 후보 목록에서 하나를 선택하세요.
2. 후보 상세 또는 검토 버튼이 있으면 클릭하세요.
3. 해당 후보에 포함된 질문 예시와 이름이 자연스러운지 확인하세요.

### 9.3 검토 시 판단 기준

아래 기준으로 판단하면 됩니다.

1. 사용자의 질문 목적이 하나로 설명되는가
2. 후보 이름이 운영자가 봐도 이해 가능한가
3. 이후 답변을 설계할 수 있을 만큼 주제가 분명한가

## 10장. 현재 버전에 반영하기

### 10.1 반영의 의미

후보 검토가 끝나면 현재 작업 중인 봇 버전에 반영할 수 있습니다.

### 10.2 반영 절차

1. **현재 버전 덮어쓰기** 또는 후보 반영 성격의 버튼을 찾습니다.
2. 현재 작업 버전에 반영한다는 의미를 확인합니다.
3. 반영 후 다음 단계로 이동할 수 있는지 확인합니다.

### 10.3 주의할 점

- 현재 버전에 덮어쓰기하는 동작은 기존 작업 내용을 바꿀 수 있습니다.
- 초보 사용자는 처음 만든 draft 버전에서 작업하는 것이 안전합니다.

## 11장. 후보별 상세 검토 후 다음 단계로 이동하기

일부 후보는 바로 `봇 제작` 단계로 이어서 볼 수 있습니다.

일반적인 흐름:

1. 후보 선택
2. 검토
3. 필요 시 `Review`
4. `봇 제작` 또는 상세 편집 화면으로 이동

이 흐름의 목적은 자동 초안을 사람이 실제 대화로 다듬는 것입니다.

## 12장. 처음 사용자 권장 작업 순서

처음 사용자라면 아래 순서를 권장합니다.

1. 학습문장 5~10개 입력
2. 후보 생성 결과 확인
3. 후보가 적절히 나뉘었는지 검토
4. 현재 버전에 반영
5. 다음 단계인 `봇 제작`으로 이동

## 13장. 자주 발생하는 문제와 해결 방법

### 13.1 후보가 너무 적게 나오는 경우

아래를 확인하세요.

1. 학습문장이 너무 적지 않은지
2. 서로 다른 질문이 한 문장 안에 섞이지 않았는지
3. 표현이 지나치게 짧거나 모호하지 않은지

### 13.2 후보가 너무 많이 쪼개지는 경우

아래를 확인하세요.

1. 같은 의미인데 표현 차이만 큰 문장을 너무 넓게 넣지 않았는지
2. 실제로는 한 주제인 문장이 분산되지 않았는지

### 13.3 무엇을 반영해야 할지 모르는 경우

처음에는 아래 기준으로만 반영하세요.

1. 이름이 분명한 후보
2. 질문 목적이 한 가지로 모인 후보
3. 다음 단계에서 답변을 만들기 쉬운 후보

## 14장. 다음 작업

`봇 구성`이 끝나면 다음 단계는 **봇 제작**입니다.

다음 단계에서는 아래 작업을 진행합니다.

1. 후보 의도 선택
2. 대화 시작 구조 확인
3. 답변 초안 수정
4. 대화 설계 저장

## 15장. 이 문서에서 확인해야 할 최종 결과

이 문서를 끝낸 사용자는 아래를 할 수 있어야 합니다.

1. `봇 구성` 화면으로 이동할 수 있다.
2. 학습문장 입력의 목적을 이해할 수 있다.
3. 의도 후보를 검토할 수 있다.
4. 현재 버전에 후보를 반영하는 흐름을 이해할 수 있다.
5. 다음 단계인 `봇 제작`으로 넘어갈 준비를 할 수 있다.
