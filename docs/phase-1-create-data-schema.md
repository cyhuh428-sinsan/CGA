# Phase 1 Create Step: Data Schema

Status: Proposal only. Not implemented.

## Purpose

This document defines the proposed data shape created by the CGA Create step.

The schema is CGA project metadata.
It should not change Aidot shared webchat, simulator, runtime variable, runtime function, or client API contracts.

## Draft Entity

Suggested name:

```text
BotSystemDraft
```

Purpose:

- Store the minimum project setup from the Create step.
- Prepare Input, Generate, Review, Configure, Build, Test, Package, Deploy, Operate, and Improve steps.
- Keep Aidot-compatible client behavior as the default external contract.

## TypeScript Shape

```ts

  id: string;

  name: string;

  deploymentIntent: CgaDeploymentIntent;
  compatibilityMode: CgaCompatibilityMode;

};
```

## Field Rules

| Field | Required | Rule |
| --- | --- | --- |
| id | yes | Generated by CGA. |
| workspaceId | yes | Must point to a CGA workspace/project owner. |
| name | yes | Unique inside workspace. |
| description | no | Human-readable summary. |
| primaryUseCase | no | Used as generator context only. |
| defaultLanguage | yes | BCP-47 language tag recommended. |
| supportedLocales | yes | Must include defaultLanguage. |
| localePolicy | yes | `single_language` or `multi_language`. |
| clientTargets | yes | Can be empty only if `decide later` behavior is approved. |
| orchestratorMode | yes | User choice from Create step. |
| deploymentIntent | yes | Planning metadata only. |
| compatibilityMode | yes | MVP default is always `aidot-compatible`. |
| status | yes | Initial value is `created`. |
| createdAt | yes | ISO datetime. |
| updatedAt | yes | ISO datetime. |

## Locale Rules

- `supportedLocales` must include `defaultLanguage`.
- Korean locale enables KakaoTalk reference adapter only if Locale Messenger is selected.
- Non-Korean locale messenger adapters are not auto-generated in MVP.
- Locale support affects generated text assets later, not the shared client API contract.

## Client Target Rules

- `web` means Aidot-compatible webchat deployment target.
- `installed_messenger` means an Aidot-compatible installed messenger adapter target.
- `locale_messenger` means an Aidot-compatible locale messenger adapter target.
- These targets do not create a CGA-only messenger protocol.

## Orchestrator Rules

- `built_in_container` prepares later generation of an orchestrator container.
- `existing_connection` prepares later entry of endpoint and credential reference.
- `decide_later` keeps the draft independent of final deployment binding.

## Mapping to Aidot Concepts

| CGA field | Aidot concept |
| --- | --- |
| name | Bot name / project name |
| defaultLanguage | Bot language/config setting candidate |
| clientTargets | Channel/client configuration concept |
| compatibilityMode | Shared client/API contract |
| orchestratorMode | New CGA metadata, not direct Aidot field |
| deploymentIntent | New CGA metadata, not direct Aidot field |

## Storage Recommendation

For CGA MVP, keep Create step metadata separate from Aidot `version_json`.

Reason:

- Create step describes CGA project and deployment planning.
- Aidot `version_json` describes bot authoring/runtime content.
- Mixing these too early could make CGA metadata look like Aidot runtime behavior.

When a bot draft becomes buildable, CGA can compile the relevant parts into Aidot-compatible runtime artifacts.

## Compatibility Impact

Shared compatibility impact: Additive CGA metadata only.

No change to:

- Aidot webchat API
- Aidot simulator API
- Aidot runtime variables
- Aidot runtime functions
- Aidot channel message payload semantics
