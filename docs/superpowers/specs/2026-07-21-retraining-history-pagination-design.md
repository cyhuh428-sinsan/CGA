# 재학습 대화 이력 페이지 조회 수정 설계

## 목적

재학습 화면이 대화 이력 API에 `page_size=500`을 전달하여 API 최대 허용값 `100`을 초과하고, `422 Unprocessable Entity`가 발생하는 문제를 해결한다.

## 확정 방식

- API의 `page_size <= 100` 보호 기준은 변경하지 않는다.
- 웹 서버/BFF가 사용하는 기존 same-origin API 경로와 인증 흐름은 변경하지 않는다.
- 재학습 화면은 한 번에 최대 100건을 조회한다.
- 첫 응답의 `total`을 기준으로 필요한 다음 페이지를 순차 조회하고 모든 `items`를 합친다.
- 화면의 `25개씩 보기`는 합쳐진 결과에 적용하는 기존 클라이언트 목록 페이지 크기로 유지한다.

## 변경 범위

- 재학습 화면의 초기 대화 이력 조회
- 사용자가 실행하는 `대화이력 동기화` 조회
- 100건 초과 및 100건 이하 응답을 검증하는 회귀 테스트

## 비변경 범위

- 관리자 대화 이력 API의 최대 페이지 크기
- 다른 관리자 이력 화면의 조회 방식
- 재학습 후보 필터, 정렬, 선택 및 저장 동작
- 운영 데이터와 DB 스키마

## 오류 처리

페이지 중 하나라도 실패하면 기존과 동일하게 조회 오류를 화면에 표시하며, 불완전한 일부 결과를 성공으로 처리하지 않는다.

## 완료 조건

1. 회귀 테스트가 기존 코드에서 `page_size=500` 때문에 실패한다.
2. 수정 후 모든 API 요청의 `page_size`가 100 이하이다.
3. 100건을 초과하는 응답은 누락 없이 다음 페이지까지 합쳐진다.
4. 타입 검사 또는 웹 빌드가 통과한다.
5. 운영 유사 또는 운영 환경의 실제 요청에서 `page_size=500`과 관련 422가 더 이상 발생하지 않는다.
