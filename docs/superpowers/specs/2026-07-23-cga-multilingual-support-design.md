# CGA Studio 7개 언어 지원 설계

## 1. 목적

CGA Studio가 한국어(`ko`), 영어(`en`), 중국어 간체(`zh-CN`), 일본어(`ja`), 베트남어(`vi`), 프랑스어(`fr`), 독일어(`de`)를 일관되게 저장·표시·처리하도록 확장한다.

이 작업에서 말하는 다국어는 다음 두 축을 모두 포함한다.

1. **화면 언어**: 메뉴, 버튼, 안내, 오류, 도움말 링크를 사용자가 선택한 언어로 표시한다.
2. **봇 언어**: 봇 생성 시 선택한 언어를 저장하고, 설정·패키지·학습·대화 실행 단계까지 동일한 언어 코드로 전달한다.

화면 언어와 봇 언어는 서로 독립적이다. 영어 화면에서 한국어 봇을 편집할 수 있고, 한국어 화면에서 일본어 봇을 편집할 수 있어야 한다.

## 2. 확인된 현재 상태

- 헤더의 언어 선택은 `aidot.language` 로컬 저장소 값만 바꾸며 화면 문구를 다시 번역하지 않는다.
- 헤더와 사용자 메뉴에는 한국어와 영어만 노출된다.
- `BotCreateRequest`, `BotUpdateRequest`와 웹 API 타입은 봇 언어를 `ko`로 제한한다.
- 기존 봇 데이터와 Aidot 패키지는 `language`, `locale`, `defaultLanguage` 필드를 사용한다.
- 한국어 ML 엔진은 Kiwi 형태소 분석, 한국어 기본 사전, 한국어 문장 특징을 사용한다.
- 운영 화면에서 영어가 선택되어 있어도 메뉴와 본문은 한국어로 표시된다.

## 3. 고정 결정

### 3.1 언어 코드

| 표시 언어 | 코드 | 비고 |
|---|---|---|
| 한국어 | `ko` | 기존 기본값 |
| English | `en` | 영어 |
| 简体中文 | `zh-CN` | 중국어는 1차로 간체 기준 |
| 日本語 | `ja` | 일본어 |
| Tiếng Việt | `vi` | 베트남어 |
| Français | `fr` | 프랑스어 |
| Deutsch | `de` | 독일어 |

기존 값이 없거나 알 수 없는 화면 언어는 `ko`로 폴백한다. API는 위 목록 이외의 새 봇 언어를 거부한다.

### 3.2 기존 한국어 동작 보존

- `ko`는 기존 Kiwi 분석기, 한국어 시스템 동의어, 한국어 특징 추출과 점수 계산을 그대로 사용한다.
- 비한국어 지원을 이유로 기존 한국어 함수의 계산식·가중치·판정 순서를 변경하지 않는다.
- 기존 DB 행의 `ko` 값과 언어 필드가 없는 구형 패키지는 계속 한국어로 읽는다.

### 3.3 API와 배포 경계

- 공개 API 경로와 응답 구조는 유지한다.
- 브라우저 요청은 계속 `/api/v1` same-origin 상대 경로를 사용한다.
- 내부 API 주소는 서버/BFF에서만 사용한다.
- DB 스키마 변경은 필요하지 않다. 현재 문자열 컬럼 범위가 모든 지원 코드를 수용한다.

### 3.4 번역 원칙

- 사용자 작성 데이터(봇명, 의도명, 학습문장, 답변)는 자동 번역하지 않는다.
- UI 고정 문구와 시스템 기본 메시지만 번역 카탈로그로 관리한다.
- 서버에서 전달되는 오류는 안정적인 오류 코드가 있으면 화면에서 번역하고, 코드가 없는 상세 진단은 원문을 보존한다.
- 번역 키가 누락되면 한국어 문구를 표시하고 개발 경고를 남긴다.

## 4. 처리 경로

### 4.1 화면 국제화

- 공용 `SupportedLocale` 타입과 언어 메타데이터를 한 파일에서 관리한다.
- React Provider가 로컬 저장소의 화면 언어를 읽고 변경 이벤트를 모든 화면에 전달한다.
- 카탈로그는 언어별 정적 파일로 분리하고, 키 타입을 한국어 기준 카탈로그에서 추론한다.
- 날짜·시간·숫자는 선택한 로케일로 표시하되 저장/API 값은 변경하지 않는다.

### 4.2 봇 언어 계약

- 생성·수정 API는 7개 언어 코드를 허용한다.
- 봇 생성·설정 화면은 동일한 공용 목록을 사용한다.
- 목록·상세·패키지 다운로드·업로드 시 언어 코드가 손실되지 않아야 한다.
- 구형 패키지의 언어 누락은 `ko`로 보정한다.

### 4.3 NLU와 답변 처리

| 단계 | 한국어 | 비한국어 |
|---|---|---|
| 제외/무시 | 기존 정규식/문자열 | 동일 계약 |
| 스몰토크 | 등록 문장 | 등록 문장 |
| Exacting Matching | 기존 정규화 | Unicode 정규화 |
| 룰 | 기존 정규식 | 동일 정규식 계약 |
| ML | 기존 Kiwi 경로 유지 | 별도 범용 Unicode 토큰/문자 n-gram 경로 |
| Semantic | 기존 모델 설정 | 다국어 임베딩 호환성 확인 및 경고 |
| LLM Intent | 기존 한국어 프롬프트 | 봇 언어를 명시한 범용 분류 프롬프트 |
| 답변 | 사용자 등록 답변/LLM | 사용자 등록 답변/LLM |

비한국어 ML 경로는 한국어 전용 어미·조사·부정 특징을 호출하지 않는다. 중국어와 일본어는 공백 의존을 피하기 위해 Unicode 문자 n-gram을 포함한다.

## 5. 사용자 흐름

1. 사용자가 헤더에서 화면 언어를 선택하면 현재 페이지를 벗어나지 않고 UI가 즉시 변경된다.
2. 사용자가 봇 생성에서 봇 언어를 선택하면 API·DB·상세 화면에 같은 코드가 저장된다.
3. 사용자가 봇 설정에서 언어를 확인·변경하면 작업 버전 정책에 따라 동일 값이 보존된다.
4. 사용자가 봇 패키지를 다운로드 후 다시 업로드해도 언어가 유지된다.
5. 사용자가 선택 언어의 학습문장으로 학습·테스트하면 해당 언어 경로가 실행된다.

## 6. 테스트와 완료 조건

- API 스키마가 7개 언어를 허용하고 그 외 코드를 거부한다.
- 한국어 기본값과 기존 한국어 NLU 회귀 테스트가 모두 통과한다.
- 봇 생성·수정·조회·Aidot 패키지 왕복에서 언어가 유지된다.
- 모든 주요 화면에서 7개 언어 선택과 번역 폴백이 동작한다.
- 언어별 대표 문장으로 룰·ML·Semantic·LLM 경로를 검증한다.
- TypeScript, Next.js 빌드, API 테스트, 운영 유사 Docker 검증을 통과한다.
- 브라우저 Network에 내부 주소나 localhost 직접 호출이 없어야 한다.

## 7. 후속 문서 작업과의 경계

제품 다국어 기능이 `main`에 통합된 뒤 별도 문서 브랜치에서 다음을 수행한다.

1. 현재 CGA 화면과 실제 기능을 기준으로 한국어 Getting Started·사용자 설명서·NLU 가이드를 보강한다.
2. Aidot 최신 사용자 매뉴얼은 공통 기능의 누락 여부를 찾는 내용 참조 자료로만 사용한다.
3. 확정된 한국어 원본을 영어·중국어 간체·일본어·베트남어·프랑스어·독일어로 번역한다.
4. 모든 DOCX/PDF를 렌더링하여 페이지별 시각 검증한 뒤 언어별 도움말 링크와 연결한다.
