## 1. 목적과 범위

### 1.1 목적

실시간 음성 통화로 챗봇과 대화할 수 있게 한다. 사용자 발화를 STT가 텍스트로 바꾸고, 기존 의도인식 런타임이 그 텍스트를 처리하고, 답변 텍스트를 TTS가 음성으로 바꿔 응답한다.

### 1.2 핵심 원칙

**기존 봇을 개조하지 않는다.** 보이스봇 유형(`bot_mode: "voice"`)으로 새 봇을 생성하고, 음성에서 성립하는 구조와 템플릿만 노출한다. 텍스트봇의 동작은 일절 바뀌지 않는다.

### 1.3 범위

| 구분 | 내용 |
|---|---|
| 포함 | 실시간 통화, STT/TTS 게이트웨이, 보이스봇 유형 제한, Talk 카드 음성 대기시간 |
| 제외 (3.0) | LLM 기반 다국어 번역 — CGA 전용 (Aidot은 다국어 미지원, 향후 계획도 없음) |
| 제외 | 텍스트봇 동작 변경, 기존 끼어들기·복귀 로직 변경 |

### 1.4 동작 흐름

```
사용자 발화
  → 게이트웨이: VAD로 발화 종료 판정
  → STT 컨테이너 API: 오디오 → 텍스트
  → CGA/Aidot 채널 API: 텍스트 → 의도인식 → 답변 텍스트
  → TTS: 텍스트 → 오디오 (사전 렌더링 캐시 우선)
  → 사용자에게 음성 재생
```

## 3. 기존 구조 재사용 — 검증된 사실

설계의 전제가 되는 사실들이며, 두 저장소를 직접 대조해 확인했다.

### 3.1 채널 엔드포인트가 제네릭하고 양쪽이 동일하다

```
Aidot channels.py:6214  @router.post("/{channel_type}/rooms/{room_id}/messages")
CGA   channels.py:6268  @router.post("/{channel_type}/rooms/{room_id}/messages")
```

엔드포인트 목록 전체가 동일하다. **게이트웨이는 접속 주소만 바꿔 양쪽에 붙는다.** 런타임 수정이 필요 없다.

### 3.2 메시지 단일 통과점이 이미 확장 가능하다

`channels.py` `_add_message()`가 사용자·봇 메시지를 모두 통과시키는 유일한 함수다.

```python
def _add_message(..., text: str, message_type: str = "text",
                 payload_json: dict[str, Any] | None = None) -> ChannelMessage
```

`message_type`과 `payload_json`이 이미 파라미터화되어 있다. **TTS 훅과 3.0 번역 훅이 모두 이 경계에 들어간다.** 새 구조를 만들 필요가 없다.

### 3.3 음성 골격이 이미 양쪽에 있다

| 자산 | 상태 |
|---|---|
| `bot_mode: Literal["text","voice"]` | 양쪽 스키마에 존재. **단, 저장만 되고 로직이 읽지 않음** |
| `transitionLocked` (의도/모듈) | 양쪽 존재. UI 라벨 "의도전환잠금" |
| `returnBlocked` (의도/모듈) | 양쪽 존재. UI 라벨 "의도복귀차단" |
| `intentTransitionLocked` (Talk 노드) | 양쪽 존재 |
| DTMF 렌더러 | 양쪽 존재. `"Voice Bot DTMF 메시지"` |
| `_dtmf_settings()` | **두 저장소에서 완전히 동일한 코드** |

### 3.4 끼어들기와 복귀가 이미 구현되어 있다

```python
_capture_runtime_return_frame(state)   # 프레임 저장
_queue_runtime_return(...)             # 복귀 예약
_restore_runtime_return(state)         # 프레임 복원
```

프레임 스택 기반이고, 복원 시 Talk 노드를 재실행해 **메시지를 다시 출력한다.** 텍스트봇에서 이미 그렇게 동작한다.

**이것이 2.0의 가장 중요한 발견이다.** 복귀 동작이 전송 방식과 무관하므로, 음성은 "카드 처음부터 재생"을 **추가 개발 없이 그대로 얻는다.** 런타임이 내보낸 텍스트를 TTS가 읽으면 끝이다.

### 3.5 Talk 노드 설정 해석이 순수 함수다

```python
def _dtmf_settings(config: dict[str, Any]) -> dict[str, Any]:   # config만 읽음. DB·상태 없음
```

**공유 패키지로 추출할 수 있는 형태의 선례다.** 음성 설정 해석도 같은 형태로 작성한다.

### 3.6 플로우 그래프가 원본 보존으로 왕복한다

```python
package["dialogFlowGraphList"] = _list(normalized.get("dialog_flow_graphs"))   # verbatim
```

노드 config가 불투명 blob으로 취급되므로 **명명 필드를 추가해도 Aidot 왕복에서 그대로 살아남는다.** `test_aidot_package_compatibility.py`의 미지 필드 보존 테스트가 이 계약을 고정하고 있다.

### 3.7 백엔드 분기율이 낮다

| 파일 | 분기 |
|---|---|
| channels.py | 6,774줄 중 122줄 (1.8%) |
| bots.py | 7,741줄 중 192줄 (2.5%) |
| admin.py | 6,920줄 중 144줄 (2.1%) |

channels.py의 122줄 차이는 **전부 CGA의 다국어 작업**이다. `core/language.py`와 `services/aidot_package_compatibility.py`는 CGA 전용 파일이다.

> **교훈**: 다국어가 공유되지 못한 이유는 `_message_language_candidates()`가 `channels.py` 안에 직접 박혀 있어서다. 보이스는 처음부터 분리된 모듈로 만들어 같은 결과를 피한다.

## 4. 아키텍처

### 4.1 3계층 분리

```
┌─────────────────────────────────────────────┐
│ 계층 1  음성 게이트웨이   [별도 저장소]        │
│   VAD · 턴 감지 · STT/TTS 호출 · 통화 제어    │
└──────────────────┬──────────────────────────┘
                   │ HTTP (채널 API)
        ┌──────────┴──────────┐
┌───────▼───────┐     ┌───────▼───────┐
│ CGA           │     │ Aidot         │
│ 적용부(상태)   │     │ 적용부(상태)   │
└───────┬───────┘     └───────┬───────┘
        └──────────┬──────────┘
        ┌──────────▼──────────────────────────┐
        │ 계층 3  공유 패키지 [별도]            │
        │   음성 설정 해석 (순수 함수만)         │
        └─────────────────────────────────────┘
        ┌─────────────────────────────────────┐
        │ 계층 2  스펙 + 적합성 테스트 [별도]    │
        └─────────────────────────────────────┘
```

### 4.2 저장소 배치와 근거

| 대상 | 위치 | 근거 |
|---|---|---|
| 음성 게이트웨이 | **별도 저장소** | 두 제품의 기능이 아니라 대등한 어댑터. 어느 한쪽에 넣으면 상대가 그 저장소를 받아와야 하는 없던 의존이 생김. 의존성(STT/TTS SDK, 오디오 코덱)·배포주기(VAD 임계값 튜닝)·운영요건(미디어 포트, 저지연)이 봇 플랫폼과 완전히 다름 |
| 음성 설정 해석 | **별도 공유 패키지** | 순수 함수. 각 저장소 침습이 import 한 줄이라 분기율을 벌리지 않음 |
| 타임아웃 적용·세션 상태 | **각 저장소** | 세션 상태에 얽혀 공유 불가 |
| 스펙 + 적합성 테스트 | **별도 저장소** | 2% 무언의 분기가 이미 존재. 테스트만이 실질적 동작 일치 보장 |
| Talk 카드 필드 정의 | **패키지 포맷 = 이미 공유 계약** | 플로우 그래프 verbatim 왕복 |

### 4.3 분리 기준

**순수 함수는 공유, 상태를 만지는 것은 각자.** 기존 코드 스타일(`_dtmf_settings`)과 일치하며 가장 안전한 경계다.

### 4.4 게이트웨이 책임 범위

게이트웨이는 **봇 설계를 알지 못한다.** 오디오↔텍스트 변환과 통화 제어만 한다.

- 통화 수립/종료, 미디어 스트림 관리
- **VAD로 턴 경계 판정** (아래 4.5 참조)
- STT/TTS 컨테이너 API 호출, 엔진 교체 가능하게 추상화
- 언어를 **설정으로** 받음 (Aidot은 `ko`만, CGA는 7개 언어)

### 4.5 VAD가 두 종류임에 주의

혼동하기 쉬운 지점이라 명시한다.

| | faster-whisper `vad_filter` | 게이트웨이 VAD |
|---|---|---|
| 시점 | 발화가 이미 끝난 뒤 | 발화 진행 중 |
| 대상 | 잘라낸 오디오 | 실시간 스트림 |
| 목적 | 무음 제거 → 환각 방지, 정확도 | **"말이 끝났다" 판정 → STT 호출 시점 결정** |

`vad_filter`는 턴 감지를 해결하지 않는다. **Talk 카드 침묵 임계값은 게이트웨이에 구현해야 한다.**

## 5. 신규 추가 항목 (최소 델타)

### 5.1 Talk 카드 음성 입력 설정

DTMF의 노드 단위 타임아웃 개념을 음성으로 확장한다. 개념이 그대로 대응된다.

| DTMF (구현됨) | 음성 (신설) | 의미 |
|---|---|---|
| `firstInputTimeoutMs` | 응답 대기 시간 | 봇 발화 후 사용자가 말을 **시작**하기까지 |
| `overallInputTimeoutMs` | 최대 발화 길이 | 계속 말할 때 자르는 한계 |
| `endCharacter` (`#`) | 침묵 임계값 | 입력 **종료** 신호. `#`이 하던 역할을 침묵이 대신함 |

**재시도 횟수는 기존 설정을 재사용한다** — `intentDetection.retryCount`, `entityPrompt.maxRepeatCount`.

**저장 방식**: 명명 필드. `messages[0..4]`는 DTMF가 사용 중이므로 인덱스 5·6을 새로 쓰지 않는다. 나중에 Aidot이 같은 자리를 다른 용도로 쓰면 왕복이 깨진다.

**필드 부재 시 동작을 스펙에 못박는다.** 구버전이 신버전 패키지를 받으면 필드는 보존하지만 해석하지 못한다. "없으면 안전한 기본값"이 정의되어 있어야 버전 스큐를 견딘다.

### 5.2 `bot_mode` 게이트 실동작화

현재 `bot_mode`는 저장만 되고 로직이 읽지 않는다. 보이스형에서 다음을 제한한다.

**응답 타입** — `TALK_RESPONSE_TYPE_OPTIONS`(flow-designer-page.tsx:215)가 필터 없는 상수 배열이다.

| 값 | 보이스형 |
|---|---|
| `none` | 허용 |
| `relay` | 허용 |
| `extract-entity` | 허용 |
| `single-select` | **차단** (버튼 선택은 음성에서 성립하지 않음) |
| `form-relay` | **차단** (JSON 응답) |

**응답 메시지 타입** — `text`, `dtmf`만 허용. `image`/`card`/`button`/`carousel`은 음성으로 읽을 수 없다.

**템플릿** — `AdminTemplate.channel_code`로 이미 채널별 구분이 있다. 음성 채널 코드를 추가해 기존 메커니즘을 그대로 쓴다.

### 5.3 TTS 훅

`_add_message()` 경계에 건다. **캐시 조회 → 미스일 때만 합성** 순서로 설계한다(6.3 사전 렌더링 참조).

- 합성 결과 오디오 참조는 `payload_json`에 저장
- `message_type`으로 오디오 여부 표시

### 5.4 원문과 변환문 분리 저장 — 필수

**재학습이 대화 이력을 학습 후보로 끌어온다.** STT 변환 텍스트나 3.0 번역문이 원문 자리에 들어가면 **학습 데이터가 오염된다.** `payload_json`에 나눠 담는 구조를 처음부터 잡는다.

- 사용자: 오디오 참조 / STT 변환 텍스트 / **STT 신뢰도**
- 봇: 답변 원문(설계 언어) / 번역문(3.0) / TTS 오디오 참조

**STT 신뢰도를 런타임 판정에 물린다.** 현재 NLU Cut-off `0.75`는 타이핑 입력 기준이다. 신뢰도 낮은 발화는 의도 판정 전에 되묻기로 보내고 **재학습 후보에서 제외**한다. 이 근거가 남지 않으면 나중에 소급 적용이 어렵다.

## 6. 엔진 선택과 설치

### 6.1 결정

| 역할 | 엔진 | 근거 |
|---|---|---|
| STT 주력 | **faster-whisper `large-v3-turbo`** (GPU) | 한국어 정확도가 오픈 옵션 중 가장 안정적. turbo로 지연 확보 |
| STT 폴백/경량 | **Moonshine** | 한국어 지원 확인(`ar es en ja ko vi uk zh`). 저지연 설계 |
| TTS | **MeloTTS** | MIT 라이선스, 한국어 지원, CPU 비교적 빠름 |
| 조건부 검토 | Supertonic | `license: openrail` — **사용 제한 조항 검토 후 판단** |
| 지연 최우선 구간 후보 | Piper | ONNX, MIT, 매우 빠름. 품질은 제한적 |
| **채택 금지** | Coqui XTTS-v2 | **CPML 라이선스로 상업적 사용 제한.** 검색 시 자주 추천되므로 명시 |

### 6.2 개발 서버 현황 (참고)

`ysna-server:~/deploy/voice`에 4개 엔진이 독립 컨테이너로 설치 중이다. 구조는 양호하다 — 서비스별 `docker-compose.yml` + `engine.env` 단일 소스, `voice-net` 공용 네트워크, 모델 캐시 볼륨.

| 엔진 | 포트 | 종류 |
|---|---|---|
| whisper | 8101 | STT |
| moonshine | 8102 | STT |
| supertonic | 8201 | TTS |
| melotts | 8202 | TTS |

**개발 서버 사양**: ARM Neoverse-N1 4코어, **GPU 없음**, 23GB 중 13GB 기사용. 기존 운영 컨테이너와 CPU 공유.

**개발 서버 실측 RTF**: whisper `base`+`int8`+`beam_size=1` → 약 1.1 / supertonic `steps=8` → 약 1.9. 둘 다 이미 속도 우선으로 조정된 값이므로 소프트웨어 여유가 없다.

이 서버는 **개발 환경이며 운영 사양은 별도로 정한다.** 다만 아래 분리는 유효하다.

| 개발 서버 측정으로 **그대로 유효** | 운영 하드웨어에서 **반드시 재측정** |
|---|---|
| 한국어 WER | RTF |
| 숫자·계좌번호·이름·상품명 인식률 | 지연 p50/p95 |
| `initial_prompt` 도메인 어휘 주입 효과 | 동시 통화 처리량 |
| 8kHz 협대역 열화폭 | TTS TTFB, GPU 메모리 |
| 기능 동작·API 계약 | |

**정확도는 하드웨어와 무관하므로 개발 서버에서 지금 검증할 수 있고 그 결과는 운영에서도 유효하다.**

### 6.3 TTS 사전 렌더링 — 엔진 선택보다 효과가 크다

콜센터 안내문은 대부분 **고정 문장 + 변수 치환**이고, CGA Talk 카드가 정확히 그 구조다.

```
"고객님, {상품명} 가입 확인 안내입니다. 동의하시면 1번을 눌러주세요."
         ^^^^^^^^ 이 부분만 동적
```

**고정 부분은 봇 배포 시점에 미리 렌더링해 오디오로 저장하고, 런타임에는 동적 조각만 합성해 이어붙인다.**

- 30초 약관 안내 → 전부 사전 렌더링. 런타임 합성 없음
- 실시간 합성은 이름·금액·상품명 같은 짧은 조각만

TTS 지연 문제가 대부분 사라지며, 엔진 선택의 부담도 줄어든다.

### 6.4 CGA 자산 활용

**① 사전(dictionary)을 STT 후처리에 쓴다.** CGA에 동의어 사전이 이미 있다(예: `삼담원 → 상담사, 상담직원`). STT 오인식 교정에 그대로 쓸 수 있다.

**② 도메인 어휘를 STT에 주입한다.** faster-whisper의 `initial_prompt`에 봇의 **의도명·개체값**을 넣으면 상품명·전문용어 인식률이 올라간다. CGA가 이미 그 목록을 갖고 있으므로 게이트웨이가 봇 컨텍스트를 받아 사용한다. **CGA와 STT를 붙여서 나오는 고유 이득이다.**

### 6.5 STT 백엔드 교체 가능하게 설계

한국어 콜센터 STT는 국내 상업 서비스가 오픈소스보다 유리한 영역이 있다(전화 8kHz 협대역, 숫자·고유명사). 다만 외부 전송에 따른 개인정보 검토와 비용 문제가 있다.

**게이트웨이에서 STT 백엔드를 추상화해 교체 가능하게 두면 이 결정을 나중으로 미룰 수 있다.** 온프레미스 납품은 오픈소스, SaaS는 상업 API를 옵션으로 두는 이중 구성도 가능하다.

## 7. 지연 예산과 인프라 요건

### 7.1 CGA 런타임 실측

```
api-cga /health/ready (DB 체크 포함) : 42~64ms
```

**CGA 쪽 여유는 충분하다.** 1초 예산 중 50ms 수준만 사용한다.

### 7.2 예산 배분

```
네트워크 + 게이트웨이 :  100ms
CGA/Aidot 런타임      :   50ms   ← 실측 완료
STT                   :  400ms
TTS 첫 오디오(TTFB)   :  300ms
여유                  :  150ms
────────────────────────────────
합계                  : 1,000ms
```

### 7.3 엔진 목표치

| 엔진 | 목표 |
|---|---|
| STT | 3~5초 발화를 400ms 내 → **RTF ≤ 0.1** |
| TTS | **RTF ≤ 0.5** + TTFB ≤ 300ms |

**TTS의 `RTF ≤ 0.5`를 강조한다.** 1.0만 넘기지 않으면 되는 게 아니다. 0.9면 이론상 재생을 따라가지만 부하 변동에 바로 끊긴다.

### 7.4 동시 통화

**목표 동시 통화 수를 먼저 정해야 운영 사양이 나온다.** 동시 N통은 처리량 N배를 요구하며, 배치 추론 또는 컨테이너 수평 확장으로 해결한다. 단일 통화 지연이 목표를 만족해도 동시 통화에서 큐 대기가 예산을 무너뜨릴 수 있다.

### 7.5 전화 음질

전화망은 **8kHz 협대역**이고 whisper는 16kHz로 학습되었다. 업샘플링해도 없는 정보는 생기지 않아 정확도가 떨어진다. **로컬 마이크 테스트 수치는 실제 통화에서 재현되지 않는다.** 모델 선택보다 이 조건에서의 측정이 먼저다.

## 8. Aidot 호환 전략

### 8.1 제품 차별화 현황

**Aidot은 다국어를 지원하지 않으며 향후 계획도 없다.** 의도된 제품 차별화다.

| 계층 | 범위 |
|---|---|
| 음성 설정 해석 (공유 패키지) | **언어 중립.** 언어를 인자로 받되 기본 `ko`, 번역 로직 없음 |
| 게이트웨이 | 언어를 파라미터로 받아 STT/TTS 음성 선택. Aidot은 `ko`만, CGA는 7개 |
| 3.0 LLM 번역 | **CGA 전용.** Aidot에는 번역 대상 언어 개념이 없음 |

**공유 패키지는 다국어를 전제하면 안 된다.** 한국어 전용 세계(Aidot)와 다국어 세계(CGA) 양쪽에서 동일하게 동작해야 한다.

### 8.2 구현 순서보다 스펙 우선

개발 에너지가 CGA에 집중되어 있다(8일간 214커밋). 이 상태에서 "Aidot 먼저"를 원칙으로 세우면 현실과 충돌하고, 역류가 없는 구조이므로 CGA에서 먼저 만든 것은 Aidot에 도달하지 못한다. 다국어가 이미 그렇게 갈렸다.

**따라서 구현 순서보다 스펙과 적합성 테스트를 먼저 확정한다.**

1. 계층 2 스펙(필드 정의 + 부재 시 기본값) 확정
2. "같은 패키지 → 같은 판정"을 고정하는 적합성 테스트 작성
3. 구현은 어디서 먼저 하든, **양쪽이 이 테스트를 통과해야 함**

이러면 구현 순서가 흔들려도 동작 일치가 유지된다.

### 8.3 공유 패키지 배포 방식 — 결정 필요

두 포크를 병행 유지하므로 공유 패키지의 배포 방식을 정해야 한다. 후보: git submodule / 사내 패키지 저장소 / vendoring. **9장 미결정 항목 참조.**

### 9.1 `speechInterruptible` 상세

논의 과정에서 입장이 두 번 바뀌었으므로 양쪽을 기록한다.

**채택 의견** (합의된 바 있음): `transitionLocked`는 **의도 전환을 막는 것**이지 **발화 중단을 막는 것**이 아니다. 텍스트에서는 메시지가 이미 전달되어 구분이 불필요했지만, 음성에서는 갈린다. 법적 고지는 TTS를 끝까지 재생해야 "고지했다"고 볼 수 있다.

**불채택 의견** (이후 분석): TTS 중단 여부는 게이트웨이의 관심사다. 게이트웨이가 사용자 발화 감지 시 TTS를 중단하고 발화를 전달하면, CGA가 `transitionLocked`로 전환을 막고 → 카드 처음부터 재생 → 고지가 다시 처음부터 읽힌다. **결과적으로 완전 전달이 보장되므로 별도 속성이 불필요하다.** 게이트웨이가 판단에 쓸 `runtimeTransitionLocked`·`runtimeReturnBlocked`도 이미 런타임 상태에 있다.

**판단 기준**: 카드별로 TTS 중단 정책을 실제로 다르게 해야 하는 사례가 있는가. 없다면 불채택이 낫다(Aidot 왕복 필드 증가 없음, 텍스트·음성 동작 규칙 단일 유지).

## 10. 검증 계획

### 10.1 적합성 테스트 (계층 2)

**코드를 공유해도 두 시스템은 시간이 지나며 어긋난다.** 실질적 보장 장치는 양쪽이 함께 돌리는 적합성 테스트다.

- "같은 봇 패키지를 넣으면 같은 판정이 나온다"를 고정
- 기존 `test_aidot_package_compatibility.py`의 왕복 무손실 테스트와 같은 패턴
- 필드 부재 시 기본값 동작도 테스트로 고정

### 10.2 엔진 벤치마크

| 항목 | 축 | 실행 환경 |
|---|---|---|
| STT 정확도 (WER) | 모델 × 엔진, **숫자·계좌번호·이름·상품명 별도 집계** | 개발 서버 (유효) |
| 음질 조건 | 16kHz vs 8kHz 다운샘플 | 개발 서버 (유효) |
| 프롬프트 효과 | 의도명·개체값 `initial_prompt` 주입 시 개선폭 | 개발 서버 (유효) |
| 환각 | 무음·노이즈 입력 시 오출력률, `vad_filter` on/off | 개발 서버 (유효) |
| STT 지연 | 모델 × `beam_size` × 동시통화(1/5/10) | **운영 하드웨어** |
| TTS 지연 | TTFB, RTF | **운영 하드웨어** |
| 전체 턴 | 발화 종료 → 첫 음성 출력 p50/p95 | **운영 하드웨어** |

**한국어 평가 샘플**은 CGA 테스트 봇의 실제 학습문장을 쓴다(`가입안했어요`, `상담사 연결해주세요` 등). 실제 도메인과 일치한다.

**우선순위**: Moonshine과 MeloTTS의 한국어 정확도·상대 속도를 먼저 측정한다. 개발 서버의 가용 범위를 결정한다.

### 10.3 텍스트봇 회귀 방지

2.0은 텍스트봇 동작을 바꾸지 않는다. 다음을 회귀 테스트로 고정한다.

- `transitionLocked`·`returnBlocked`·프레임 복귀 동작 불변
- `TALK_RESPONSE_TYPE_OPTIONS` 제한이 `bot_mode: "text"`에는 적용되지 않음
- `messages[0..4]` DTMF 위치 규약 불변
- Aidot 패키지 왕복 무손실 유지

## 11. 3.0 연결점

3.0(LLM 번역)은 **2.0과 같은 훅 지점에 얹힌다.** 별도 계층 신설이 필요 없다.

이미 갖춰진 언어 컨텍스트:
- 채널 요청의 `language` 필드
- 대화방 언어 `room.metadata_json["language"]` (channels.py:130)
- 언어 우선순위 해석기 `_message_language_candidates()`
- 7개 언어 런타임 (검증 완료)

3.0에서 할 일은 "번역 계층 신설"이 아니라 **이미 있는 언어 컨텍스트에 LLM 번역 한 단계를 끼우는 것**이다. 단, **CGA 전용**이다(8.1 참조).

5.4의 원문/변환문 분리 저장이 3.0의 전제 조건이므로 2.0에서 미리 잡는다.
