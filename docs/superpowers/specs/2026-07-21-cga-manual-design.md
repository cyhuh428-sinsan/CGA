# CGA Studio 사용자 메뉴얼 설계서

작성일: 2026-07-21
상태: 설계 승인

## 1. 목적

CGA Studio의 일반 사용자와 봇·대화 설계 운영자가 실제 화면에서 기능을 사용할 수 있도록 통합 사용자 메뉴얼을 작성한다. Aidot 사용자 메뉴얼은 용어와 설명 순서를 참고하되, 본문에는 CGA에서 실제 확인된 기능만 수록한다.

## 2. 산출물과 기준

- Markdown 원본을 단일 기준으로 관리한다.
- 검토 완료 후 Markdown을 Word와 PDF로 변환한다.
- 기존 Aidot 참고자료 위치: `docs/manual/aidot-user-manual`
- 기존 `docs/manual/` 자료는 참고자료로 보호하며, 본 설계 작업에서 수정하지 않는다.

## 3. 범위

### 포함

- CGA Studio 시작과 공통 화면
- 일반 사용자 업무 흐름
- 운영자 업무 흐름
- 실제 확인이 끝난 메뉴별 상세 설명
- CGA와 Aidot 용어 대응표

### 제외

- Aidot에는 있으나 CGA에서 확인되지 않은 기능의 사용 절차
- 소스에만 존재하고 실제 화면·동작이 확인되지 않은 기능의 확정적 설명
- 개발자용 API·DB·CLI 운영 설명
- 메뉴얼 목적과 무관한 코드 리팩터링이나 화면 변경

## 4. 기능 확인 원칙

기능 설명의 근거는 다음 순서로 적용한다.

1. CGA 실제 화면·클릭·저장 결과
2. CGA 소스와 API에서 확인되는 현재 기능
3. Aidot 메뉴얼의 용어·설명·화면 구성

내부 검토표에는 각 기능을 `확인 완료`, `부분 확인`, `미수록`으로 표시한다. 사용자용 본문에는 `확인 완료` 기능만 수록하고, 나머지는 별도 검토 목록에서 추적한다.

## 5. 문서 구조

### 1부. CGA Studio 시작하기

- CGA Studio 소개
- 로그인과 기본 화면
- 화면 구성과 공통 버튼
- 사용자 권한별 접근 범위

### 2부. 일반 사용자 업무 흐름

- 봇 목록 확인
- 봇·버전 확인
- 대화 결과 확인
- 테스트·분석·평가 기능

### 3부. 운영자 업무 흐름

- 사용자·그룹 관리
- 봇·버전 운영
- 대화 설계 관리
- 의도·개체·사전 관리
- 채널·봇스테이션 관리
- 템플릿·공통 변수·기본 메시지 관리
- 학습·운영 상태 확인

### 4부. 메뉴별 상세 설명

모든 메뉴는 다음 형식을 따른다.

- 목적
- 접근 경로
- 화면 구성
- 사용 절차
- 저장·적용 시 주의사항
- 오류·제한사항
- 관련 업무 흐름

### 5부. 부록

- CGA와 Aidot 용어 대응표
- 권한별 접근 메뉴표
- 기능 확인 상태 목록
- 변경 이력

## 6. 작성 규칙

- 화면의 실제 메뉴명과 버튼명을 우선 사용한다.
- Aidot와 CGA의 명칭 또는 동작이 다르면 CGA 기준으로 작성하고 차이를 명시한다.
- 확인하지 않은 동작은 추측으로 작성하지 않는다.
- 각 절차는 사용자가 화면에서 따라 할 수 있는 순서로 작성한다.
- 설명은 목적과 조작 결과 중심으로 쓰고 내부 구현 세부사항은 제외한다.
- 화면 캡처에는 메뉴 경로와 핵심 조작 위치를 표시한다.
- 기능별로 필요한 권한과 저장·적용 시점을 함께 기록한다.

## 7. 검증 기준

메뉴얼 초안은 다음을 확인한 뒤 완료로 판정한다.

- 본문에 미확인 기능이 확정적으로 포함되지 않았는가
- 메뉴명·버튼명·접근 경로가 현재 CGA 화면과 일치하는가
- 절차를 처음 보는 사용자가 순서대로 따라갈 수 있는가
- 저장·적용·오류 조건이 누락되지 않았는가
- 기존 Aidot 참고자료와 용어 대응이 필요한 부분이 표시되었는가
- Markdown 원본이 정상적으로 렌더링되는가
- Word/PDF 변환 후 화면 캡처와 표가 깨지지 않는가

## 8. 단계별 작성 순서

1. CGA 메뉴와 화면을 확인하고 기능 확인표를 만든다.
2. 1부와 2부를 작성한다.
3. 3부와 4부를 작성한다.
4. 부록과 미확인 기능 목록을 정리한다.
5. 화면 캡처를 삽입하고 Markdown 자체 검토를 수행한다.
6. 사용자 검토 후 Word와 PDF로 변환하고 시각 검증한다.

## 9. 설계상 주의사항

현재 저장소에는 `docs/manual/` 아래에 기존 메뉴얼·캡처·QA 자료가 미커밋 상태로 존재한다. 이 자료는 사용자 작업물일 수 있으므로 메뉴얼 작성 시 삭제·이동·일괄 정리하지 않는다. 실제 브라우저 검증이 완료되지 않은 기능은 메뉴얼 작성 근거로 사용하지 않는다.
