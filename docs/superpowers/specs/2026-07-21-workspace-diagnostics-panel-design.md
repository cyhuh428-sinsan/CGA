# 봇 작업공간 진단 패널 설계

## 목적

봇 작업공간 오른쪽의 정적 `시뮬레이터 미리보기`를 운영자가 현재 선택한 봇의 평가 이상 항목을 바로 확인할 수 있는 진단 영역으로 교체한다.

## 화면 구성

- 오른쪽 열을 같은 높이의 세 영역으로 나눈다.
- 위에서부터 `오분류 문장`, `낮은 Score 문장`, `유사 의도 충돌`을 표시한다.
- 각 영역은 제목, 열 머리글 또는 항목명, 데이터 목록, 빈 상태로 구성한다.
- 데이터가 없을 때는 각각 `오분류 문장이 없습니다.`, `낮은 Score 문장이 없습니다.`, `충돌 없음`을 표시한다.
- 전역 시뮬레이터 버튼은 진단 영역에 포함하지 않고 화면 오른쪽 아래의 기존 고정 버튼 형태로 표시한다.

## 데이터 흐름

- 별도 API를 추가하지 않는다.
- 현재 `fetchStudioWorkspaceContext`로 받은 선택 버전의 `version_json.system_config.nlu_evaluation.snapshot.training_rows`를 사용한다.
- 저장된 평가 행을 화면용 형태로 정규화한다.
- 오분류 문장은 `correct === false`인 행, 낮은 Score 문장은 Score가 70 미만인 행을 최대 10개까지 표시한다.
- 유사 의도 충돌은 오분류 행의 정답 의도와 예측 의도 쌍을 집계해 빈도순 최대 6개를 표시한다.
- 봇 또는 버전을 바꾸면 기존 작업공간 컨텍스트 갱신에 맞춰 진단 내용도 함께 갱신한다.

## 변경 범위

- `apps/web/components/bot-operations-workspace-page.tsx`
  - 평가 스냅샷 정규화 및 진단 목록 계산
  - 정적 시뮬레이터 미리보기 제거
  - 세 진단 패널과 전역 시뮬레이터 실행 버튼 표시
- `apps/web/components/simulator-page.tsx`
  - 작업공간의 선택 봇 UUID와 버전을 실행기에 전달하는 선택 속성 추가
- `apps/web/app/globals.css`
  - 오른쪽 열의 3등분 진단 레이아웃과 표 스타일
  - 더 이상 사용하지 않는 작업공간 전용 정적 시뮬레이터 미리보기 스타일 제거
- 관련 UI 계약 테스트
  - 세 진단 제목과 전역 시뮬레이터 실행기 존재 확인
  - 정적 시뮬레이터 미리보기 제거 확인

## 기존 기능 유지

- 봇 선택, 그룹 정보, 최근 작업 봇, 작업 항목, 저장 버튼과 상세 화면 이동은 변경하지 않는다.
- 브라우저 API 호출 경로와 `fetchStudioWorkspaceContext` 호출 방식은 변경하지 않는다.
- 평가 화면 자체의 진단 표와 시뮬레이터 동작은 변경하지 않는다.

## 오류 및 빈 상태

- 평가 스냅샷이 없거나 행 형식이 올바르지 않으면 해당 행을 무시하고 빈 상태를 표시한다.
- 기존 작업공간 컨텍스트 조회 오류 메시지 처리는 유지한다.
- 진단 표시 오류가 봇 작업공간 전체 렌더링을 막지 않도록 입력 데이터를 방어적으로 정규화한다.

## 검증

- UI 계약 테스트로 제목, 데이터 기준, 정적 미리보기 제거, 시뮬레이터 실행기 표시를 확인한다.
- `apps/web` 타입 검사와 빌드를 실행한다.
- 로컬 운영 유사 화면에서 봇 작업공간을 열어 오른쪽 열 3등분, 빈 상태 또는 실제 데이터, 오른쪽 아래 시뮬레이터 버튼을 확인한다.
- 시뮬레이터 버튼을 실제 클릭해 팝업이 열리는지 확인한다.
- 브라우저 Network에서 내부 API 절대주소나 localhost 직접 호출이 새로 생기지 않았는지 확인한다.
