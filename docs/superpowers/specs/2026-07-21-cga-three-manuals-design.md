## 3. 문서별 역할

### 3.1 CGA 사용자 설명서

대상은 일반 사용자와 운영자다. CGA의 전체 메뉴와 업무 절차를 설명한다.

주요 범위:

- CGA Studio 시작과 공통 화면
- 봇·버전 관리
- 대화 설계
- 의도·개체·사전
- 테스트·분석·평가
- 채널·봇스테이션
- 관리자 기능
- 오류·주의사항

각 기능은 목적, 접근 경로, 화면 구성, 사용 절차, 저장·적용 결과, 제한사항 순서로 작성한다.

### 3.2 CGA Getting Started

처음 사용하는 사람이 안내를 따라 첫 테스트 결과를 확인하는 것을 목표로 한다. 기능을 모두 설명하지 않고 첫 성공 경로를 제공한다.

기본 흐름:

`로그인 → 봇 생성 → 기본 정보 입력 → 엔진 선택 → 최소 데이터 입력 → 학습 또는 인덱스 생성 → 테스트 → 결과 확인`

작성 원칙:

- 한 단계에 한 가지 작업만 안내한다.
- 모든 단계는 `목적 → 조작 → 예상 결과` 형식으로 작성한다.
- 실제 CGA 화면 캡처에 클릭 위치와 입력 위치를 표시한다.
- 어려운 용어는 처음 등장한 위치에서 짧게 설명한다.
- 성공 결과와 실패 시 다음 조치를 함께 제시한다.
- 첫 과정에서는 고급 설정과 예외적인 운영 기능을 제외한다.
- 각 단계 끝에 다음 단계로 이동할 수 있는 문장을 둔다.
- 상세한 엔진 원리와 품질 개선은 NLU 활용 가이드로 연결한다.

엔진 선택 단계에서는 다음 수준으로만 설명한다.

- ML: 의도와 학습문장을 중심으로 분류한다.
- Semantic: 의미 유사도와 벡터 검색을 중심으로 분류한다.
- LLM: LLM 모델과 지시문을 활용해 분류·답변한다.

엔진 선택 이후에는 ML·Semantic·LLM별로 짧은 실행 경로를 분기한다. 분기마다 최소 입력, 실행 또는 학습 단계, 테스트 방법, 성공 결과를 설명한다.

### 3.3 CGA NLU 활용 가이드

대상은 봇·대화 설계 운영자와 AI/NLU 전문 담당자다. 운영자가 엔진을 선택하고 데이터를 준비하며 품질을 개선할 수 있도록 작성한다.

구성:

1. NLU 기본 개념과 용어
2. ML·Semantic·LLM 비교와 선택 기준
3. ML 엔진 활용
4. Semantic 엔진 활용
5. LLM 엔진 활용
6. 테스트·평가·분석
7. 품질 개선과 오류 대응
8. 운영 기준과 사례
9. 용어·설정값·엔진 비교 부록

엔진별 장에는 공통적으로 다음 내용을 포함한다.

- 엔진의 역할과 적합한 사용 사례
- 봇 생성·설정 방법
- 필요한 데이터와 작성 규칙
- 학습·인덱스 생성·모델 적용 절차
- 테스트와 평가 방법
- 분석 결과 해석
- 품질 개선 절차
- 제한사항과 오류 대응

## 4. 엔진 설명 기준

세 엔진은 개념 설명만으로 끝내지 않고 설정·데이터·실행·검증·운영까지 비교한다.

| 구분 | ML | Semantic | LLM |
|---|---|---|---|
| 핵심 설명 | 의도·학습문장 중심 분류 | 임베딩·벡터 유사도 중심 분류 | LLM 모델·지시문 기반 분류·답변 |
| 준비 데이터 | 의도, 학습문장, 개체, 사전 | 의도, 학습문장, 임베딩·Vector DB 설정 | 의도, 지시문, Provider·모델 설정 |
| 주요 검증 | 정확도, 오분류, 학습문장 균형 | 유사도, 임계값, 검색 품질 | 응답 일관성, 지시문 준수, 비용·지연 |
| 주요 주의점 | 의도 간 중복과 데이터 불균형 | 임베딩 호환성과 인덱스 재생성 | 모델 변경, 프롬프트, 응답 편차 |

이 표는 설계 기준이며, 실제 설명 문구와 지원 범위는 CGA 화면·API·실행 검증 결과에 맞춰 확정한다.

## 5. 문서 간 연결 규칙

- Getting Started의 상세 엔진 설명은 NLU 활용 가이드의 해당 장으로 연결한다.
- 사용자 설명서의 메뉴 절차는 Getting Started의 첫 사용 흐름과 중복되는 부분을 짧게 요약한다.
- NLU 활용 가이드에서 화면 조작이 필요한 경우 사용자 설명서의 메뉴별 상세 설명을 연결한다.
- 세 문서에서 같은 기능을 설명할 때 메뉴명·버튼명·상태명은 동일하게 유지한다.
- 문서에 없는 기능은 참고자료에 있다는 이유만으로 링크하거나 기능으로 소개하지 않는다.

## 6. 검증 기준

### Getting Started

- CGA에 처음 접속한 사용자가 문서만 보고 첫 테스트까지 진행할 수 있는가
- 각 단계에 입력값, 클릭 대상, 예상 결과가 있는가
- 엔진별 분기에서 필요한 최소 조건이 누락되지 않았는가
- 실패 시 사용자가 다음 조치를 알 수 있는가
- 실제 화면 캡처와 현재 UI가 일치하는가

### 사용자 설명서

- 메뉴명과 접근 경로가 현재 CGA와 일치하는가
- 권한과 저장·적용 시점이 설명되어 있는가
- 일반 사용자와 운영자의 설명 범위가 혼동되지 않는가

### NLU 활용 가이드

- ML·Semantic·LLM의 차이와 선택 기준이 명확한가
- 엔진별 데이터·학습·테스트·분석 절차가 구분되는가
- 확인되지 않은 엔진 동작을 확정적으로 설명하지 않는가
- 운영자가 품질 저하 원인과 개선 절차를 찾을 수 있는가

## 7. 작성 순서

1. CGA 실제 메뉴·화면·엔진 설정을 확인한다.
2. Getting Started의 공통 흐름과 엔진별 최소 성공 경로를 작성한다.
3. 사용자 설명서의 공통 기능과 메뉴별 상세 설명을 작성한다.
4. NLU 활용 가이드의 엔진별 장과 품질 개선 절차를 작성한다.
5. 세 문서의 용어·링크·화면 캡처를 대조한다.
6. Markdown 검토 후 Word/PDF로 변환하고 시각 검증한다.
