# 로그인 화면 활성화 보호 설계

## 목적

- React가 활성화되기 전에 로그인 폼이 기본 GET 방식으로 제출되는 것을 방지한다.
- `master/master` 인증과 기존 5173 프록시 구조는 그대로 유지한다.

## 변경 범위

- `apps/web/app/login/page.tsx`에 화면 활성화 상태를 추가한다.
- 초기 서버 렌더링에서는 로그인 버튼을 비활성화하고 `화면 준비 중...`을 표시한다.
- 클라이언트 `useEffect` 완료 후 기존 로그인 버튼과 제출 동작을 활성화한다.

## 제외 범위

- 인증 API, 데이터베이스, 세션 형식, 로그인 후 이동 경로는 변경하지 않는다.
- 8321 API 직접 호출로 전환하지 않는다.
- 시작 스크립트의 준비 로직은 이번 수정에 포함하지 않는다.

## 오류 처리

- 화면 활성화 실패 시 버튼은 비활성화 상태로 남아 기본 폼 제출과 `/login?` 이동을 막는다.
- 활성화 이후의 API 오류 표시는 기존 오류 메시지 처리를 유지한다.

## 검증

1. 변경 전 로그인 버튼에 활성화 보호가 없어 검증이 실패하는지 확인한다.
2. 변경 후 초기 버튼이 비활성화되고 활성화 이후 기존 제출이 가능함을 확인한다.
3. 5173 프록시로 `master/master` 로그인 응답과 토큰 발급을 확인한다.
4. 로그인 화면과 대시보드가 HTTP 200인지 확인한다.

## 영향

- 로그인 화면이 활성화되기 전에는 버튼을 누를 수 없다.
- 활성화 이후의 로그인 흐름과 기존 기능은 변경되지 않는다.
