1. Executive Summary
Chatbot Generator Agent(CGA)는 사용자가 입력한 학습 문장과 PDF 지식을 기반으로 의도(Intent), 답변 방식, 시나리오, RAG 지식, 배포 채널을 자동 구성하는 챗봇 생성·운영 플랫폼이다.
핵심은 모든 질문을 LLM으로 처리하는 것이 아니라, 빌드 단계에서는 LLM을 활용해 의도와 질문 후보를 생성하고, 런타임 단계에서는 ML 엔진·자체 시멘틱 엔진·외부 시멘틱 엔진·LLM RAG를 목적별로 조합하는 하이브리드 구조다.
따라서 이 시스템의 본질은 “챗봇을 한 번 생성하는 도구”가 아니라, 의도 생성, 운영자 검수, 시나리오 구성, 배포, 미정의 질문 감지, 신규 의도 승인까지 포함하는 챗봇 생애주기 관리 시스템이다.

3. 시스템 목표와 비목표
3.1. 목표
비개발자 또는 운영자가 복잡한 프롬프트 엔지니어링 없이 챗봇 초안을 생성할 수 있게 함.
학습 문장 기반 의도 분류와 PDF 기반 질문 추출을 자동화함.
운영자가 의도와 답변, 시나리오를 화면에서 검수·편집할 수 있게 함.
런타임 비용을 낮추기 위해 자체 시멘틱 엔진을 핵심 라우팅 수단으로 활용함.
사전에 정의되지 않은 질문을 신규 의도 후보로 전환하고 승인 후 템플릿에 반영함.
Web, 설치형 프로그램, 카카오톡을 공통 런타임 API에 연결함.
공용 SaaS형 배포와 고객사 독립 컨테이너 배포를 모두 지원함.
3.2. 비목표
초기 버전에서 모든 업무 자동화 API와 모든 메신저 채널을 지원하는 것은 비목표.
모든 질문을 LLM으로 처리하는 범용 AI 플랫폼을 만드는 것은 비목표.
운영자 승인 없이 LLM이 생성한 신규 의도와 프롬프트를 즉시 운영 반영하는 것은 비목표.
Dify, Copilot Studio 등 기성 플랫폼 전체 기능을 복제하는 것은 비목표.

6. 빌드 단계 운영 흐름
6.1. 질문형 학습 문장 기반 챗봇 생성
운영자가 질문 형태의 학습 문장 더미를 업로드하거나 붙여넣음.
운영자가 생성할 의도 개수 N을 입력함.
LLM이 문장 간 의미 유사도와 주제를 분석하여 N개의 의도 후보를 생성함.
운영자는 의도 후보를 그대로 사용하거나 병합·삭제·추가함.
각 의도에 고정 답변, 시멘틱 RAG, LLM RAG, 인터넷 검색 답변 중 하나를 매핑함.
필요 시 고급 사용자가 시나리오 에디터에서 조건 분기와 후속 흐름을 구성함.
검수 완료 후 Chatbot Dynamic Template으로 컴파일함.
6.2. PDF 지식 기반 챗봇 생성
운영자가 PDF 지식 문서를 업로드함.
운영자가 문서에서 추출할 예상 질문 또는 의도 개수 M을 입력함.
시스템이 PDF를 파싱하고 청크 단위로 분리함.
LLM이 문서 핵심 내용을 기반으로 실제 사용자가 물어볼 가능성이 높은 질문 후보를 생성함.
시스템이 PDF 기반 RAG 색인을 구축함.
운영자는 질문 후보를 추가·삭제하고 의도별 답변 유형을 선택함.
검수 완료 후 PDF RAG 설정과 의도 라우팅 규칙이 템플릿에 포함됨.

8. 미정의 질문 감지 및 동적 의도 확장
이 설계의 핵심 차별점은 런타임에서 Unknown Intent를 단순 로그로 남기는 데 그치지 않고, 신규 의도 후보와 프롬프트를 생성하여 운영자 승인 흐름으로 연결한다는 점이다.
사용자 질문이 기존 의도와 충분히 매칭되지 않으면 Unknown Intent로 분류함.
시스템은 해당 질문과 RAG 검색 결과를 함께 분석해 신규 의도 후보를 생성함.
신규 의도에 필요한 프롬프트, 샘플 질문, 추천 답변 유형을 자동 생성함.
상태를 PENDING_APPROVAL로 저장하고 운영자 대시보드에 승인 요청 알림을 표시함.
운영자가 승인하면 기존 템플릿에 의도와 프롬프트를 병합함.
운영자가 반려하면 해당 질문은 학습 제외 또는 별도 보류 상태로 관리함.

9. 시나리오 에디터 설계
의도에 단순 답변을 바로 입력할 수도 있지만, 고급 사용자는 시나리오를 구성할 수 있어야 한다. 단, Dify류의 자유 노드 방식은 강력하지만 복잡도가 높기 때문에, 초기 제품은 “제한된 자유도”를 가진 실무형 에디터가 더 현실적이다.
구성 요소
설명
Scenario Node
대화 흐름의 한 단계. 질문, 답변, 조건, 액션 중 하나를 가짐
Condition Branch
사용자 응답, 엔티티, 권한, 채널, 이전 상태에 따른 분기

9.1. 시나리오 에디터 MVP 원칙
초기 버전은 완전 자유 노드 그래프보다 “폼 기반 + 제한된 분기”가 안전함.
일반 운영자는 의도별 답변 매핑만 사용하게 하고, 시나리오 기능은 고급 모드로 분리하는 것이 현실적임.
노드가 많아질수록 유지보수가 급격히 어려워지므로, 노드 수 제한·순환 참조 방지·미연결 노드 검사를 필수로 둬야 함.
시나리오 배포 전 테스트 대화 시뮬레이터가 반드시 필요함.

10.3. 라우팅 원칙
정확성과 비용을 동시에 고려하여 “가벼운 엔진 먼저, 무거운 엔진 나중” 순서로 라우팅함.
고정 답변으로 충분한 의도는 LLM 호출을 금지하는 옵션이 필요함.
시멘틱 엔진 점수가 임계치 이상이면 LLM을 호출하지 않음.
RAG 근거가 부족하면 LLM이 임의 답변을 만들지 못하도록 Fallback을 우선 적용함.
인터넷 검색 답변은 보안·정책상 허용된 챗봇 또는 의도에만 제한적으로 열어야 함.

20. 결론
Chatbot Generator Agent는 단순한 챗봇 빌더가 아니라, 챗봇 생성·검수·배포·운영·개선까지 포함하는 운영형 챗봇 팩토리 아키텍처다.
가장 강한 차별점은 4×4 NLU·답변 매트릭스와 자체 시멘틱 엔진 중심의 비용 방어 구조다. 이 구조가 실제로 높은 의도 매칭 정확도와 낮은 운영 비용을 증명한다면, 범용 LLMOps 플랫폼과 다른 명확한 시장 포지션을 만들 수 있다.
반대로 시나리오 에디터가 복잡해지고, 자체 시멘틱 엔진 품질이 낮으며, 동적 의도 확장이 운영자에게 노이즈로 느껴지면 제품 가치는 크게 약해진다. 따라서 다음 단계는 기능을 많이 추가하는 것이 아니라, 핵심 루프인 “의도 생성 → 운영자 수정 → 자체 엔진 라우팅 → 미정의 질문 승인”의 품질을 먼저 수치로 검증하는 것이다.
