신산님, 아래는 화면 구성 기준 CGA 설계서 초안입니다.
전제는 명확합니다.
CGA는 Aidot 기능을 새로 만드는 것이 아니라, Aidot의 기존 기능을 봇 제작 순서대로 다시 배치하는 Studio 화면이다.
CGA Studio 설계서 초안
1. 목적
CGA Studio는 Aidot에 이미 구현된 봇 생성, 설정, 구성, 의도, 학습문장, PDF/RAG, 학습, 시뮬레이터, 평가, 분석, 배포 기능을 사용자가 봇을 제작하는 실제 순서에 맞게 재구성한 화면이다.
Aidot는 기능 중심 화면이다.
CGA는 작업 순서 중심 화면이다.
2. 핵심 원칙
Aidot 구조, 기능, API, 런타임은 유지한다.
CGA에서 새 기능 개발은 기본 금지다.
새 기능이 필요하면 반드시 **“새로운 기능 개발 요청”**으로 신산님 승인 후 진행한다.
CGA의 핵심 개발 대상은 기능 자체가 아니라 화면 구성과 작업 흐름이다.
CGA Studio는 멀티랭귀지를 기본으로 한다.
Aidot는 한국어 기준이므로, CGA는 화면 라벨과 사용자 흐름을 멀티랭귀지 기준으로 재정리한다.

단, Aidot 내부 기능은 제거하지 않는다.
CGA 화면에서 봇 구성 흐름만 LLM 기준으로 제한 노출한다.
3단계. Configure
목적: 봇의 초기 의도 구성을 만든다.
CGA에서 가장 중요한 화면이다.
구성 방식은 두 가지다.
A. 학습문장 입력 → 의도 분류
사용자가 학습문장을 입력하거나 파일로 넣는다.
원하는 의도 개수를 지정한다.
프롬프트와 학습문장을 구성한다.
LLM 엔진이 연결되어 있으면 시스템이 직접 LLM 호출한다.
LLM 엔진이 연결되어 있지 않아도 가능해야 한다.
이 경우 CGA는 프롬프트와 학습문장 파일을 만들어 사용자가 외부 LLM에 전달할 수 있게 한다.
사용자가 외부 LLM 답변을 가져와 입력하면 CGA가 의도 구성을 반영한다.
B. PDF 입력 → 질문/답변 의도 생성
사용자가 PDF를 입력한다.
PDF에서 예상 질문과 답변으로 이루어진 의도 후보를 만든다.
이 방식은 LLM이 연결된 경우에만 가능하다.
LLM 연결이 없으면 이 화면은 비활성 또는 안내 상태로 둔다.

6. 승인 필요 항목
신산님 승인 전에는 구현하지 않는다.

초안 결론:
CGA Studio의 핵심은 Aidot 기능을 줄이거나 새로 만드는 것이 아니라, 봇 제작자가 “다음에 무엇을 해야 하는지” 알 수 있도록 Aidot 기능을 제작 순서대로 다시 디자인하는 것이다.
