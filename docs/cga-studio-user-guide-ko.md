# CGA Studio 사용자 가이드

## 1. 문서 목적
- 이 문서는 `http://127.0.0.1:4173/` 에 올라간 CGA Studio를 신산님이 직접 따라가며 테스트할 수 있도록 만든 사용자 가이드입니다.
- 기준일: `2026-06-18`
- 기준 브랜치: `codex/wsl-container-dev`
- 기준 커밋: `7635838 fix: align workspace and dashboard surfaces`

## 2. 접속 기준
- 접속 주소: `http://127.0.0.1:4173/`
- 실행 기준:
  - WSL 배포 경로: `~/deploy/cga`
  - Docker 서비스: `studio`
  - 컨테이너: `cga-studio`

## 3. 테스트 전 확인
1. 브라우저 주소가 `http://127.0.0.1:4173/` 인지 확인합니다.
2. 로그인 후 첫 화면이 `봇 작업공간`인지 확인합니다.
3. 상단 우측에 `저장` 버튼만 보이고, `배포` 버튼은 운영 화면이 아닐 때 숨겨지는지 확인합니다.

## 4. 권장 테스트 순서

### 4.1 로그인
1. 로그인 화면에서 계정을 입력합니다.
2. 로그인에 성공하면 첫 화면이 `봇 작업공간`으로 이동해야 합니다.
3. 상단 컨텍스트에 현재 사용자, 그룹, 봇, 버전이 보여야 합니다.

### 4.2 봇 작업공간
확인 목표: 작업할 그룹과 봇을 고를 수 있어야 합니다.

1. 좌측 메뉴에서 `봇 작업공간`을 선택합니다.
2. `그룹 선택`에서 작업 그룹을 확인합니다.
3. `그룹 봇 목록`에 봇 목록이 보여야 합니다.
4. 목록에서 봇을 클릭하면 우측 `현재 작업 대상`이 바뀌어야 합니다.
5. 하단 `작업 봇 열기`를 누르면 `봇 설정` 화면으로 이동해야 합니다.
6. 우측 빠른 이동 버튼으로 아래 이동이 가능해야 합니다.
   - `봇 설정 열기`
   - `봇 구성 열기`
   - `봇 관리 열기`

실제 확인 결과:
- `Support Bot Group` 기준으로 봇 목록이 표시되는 것 확인
- `supportbot-draft`, `faqbot-v1` 노출 확인

### 4.3 새 봇 생성
확인 목표: 새 봇 초안 생성 후 생성 화면으로 들어갈 수 있어야 합니다.

1. `봇 작업공간`에서 `+ 봇 생성`을 누릅니다.
2. 화면이 `봇 생성`으로 이동해야 합니다.
3. 새 draft 봇이 현재 작업 봇으로 잡혀야 합니다.
4. `봇 이름`, `설명`, `기본 언어`, `버전 이름`을 확인합니다.
5. 상단 `저장` 버튼을 누릅니다.
6. 저장 후 상단 또는 메시지 영역에 저장 완료 문구가 보여야 합니다.

실제 확인 결과:
- `+ 봇 생성` 클릭 시 `봇 생성` 화면 진입 확인
- 저장 후 `현재 작업 내용을 서버에 저장했습니다.` 문구 확인

### 4.4 봇 관리
확인 목표: 봇 단위 자산/버전 관리가 가능해야 합니다.

1. 좌측 메뉴에서 `봇 관리`를 선택합니다.
2. 좌측에 봇 목록이 보이는지 확인합니다.
3. 중앙에 버전 목록이 보이는지 확인합니다.
4. 우측에 아래 정보가 보이는지 확인합니다.
   - 봇 ID
   - 봇 이름
   - 운영버전
   - WebChat 주소
5. `버전 추가`를 누릅니다.
6. 새 버전이 목록에 추가되는지 확인합니다.
7. `운영 설정`, `복사`, `삭제` 버튼이 각 버전 행에 보이는지 확인합니다.
8. `봇 다운로드`, `봇 업로드` 버튼이 보이는지 확인합니다.

실제 확인 결과:
- `버전 추가` 클릭 후 `v0.2` 생성 확인
- 상태 문구 `버전 v0.2가 추가되었습니다. / 서버 저장` 확인

### 4.5 팀 대시보드
확인 목표: 협업 현황과 승인 흐름이 보이고, 승인 동작이 반영되어야 합니다.

1. 좌측 메뉴에서 `팀 대시보드`를 선택합니다.
2. 상단 요약에 아래 항목이 보여야 합니다.
   - 내 작업
   - 검토 대기
   - 승인 필요
   - 잠금 상태
   - 전체 작업
3. 본문에서 아래 섹션이 보여야 합니다.
   - 내 작업
   - 검토 대기
   - 차단 항목
   - 그룹별 진행률
   - 봇별 진행률
   - 권한별 할 일
   - 작업 상태
   - 최근 수정 이력
   - 병목 항목
   - 담당자별 작업량
4. `검토 대기` 카드의 `승인` 버튼을 누릅니다.
5. 승인 후 `검토 대기` 건수가 감소하는지 확인합니다.

실제 확인 결과:
- `최근 수정 이력`, `병목 항목`, `담당자별 작업량` 섹션 존재 확인
- `승인` 클릭 후 `검토 대기 0건` 반영 확인

### 4.6 봇 생성 화면 저장 규칙
확인 목표: 전역 저장 버튼이 실제 저장 동작과 연결되어야 합니다.

1. `봇 생성` 화면에서 필드를 하나 수정합니다.
2. 상단 `저장` 버튼을 누릅니다.
3. 저장 완료 메시지가 보이는지 확인합니다.
4. 다시 같은 화면을 열었을 때 값이 유지되는지 확인합니다.

실제 확인 결과:
- 전역 `저장` 버튼 동작 확인

## 5. 화면별 역할 정리

### 5.1 봇 작업공간
- 어떤 그룹의 어떤 봇을 작업할지 선택하는 화면
- 현재 작업 봇 확인
- 최근 작업 봇 확인
- 봇 설정/구성/관리로 이동

### 5.2 봇 관리
- 이미 생성된 봇의 자산과 버전을 관리하는 화면
- 버전 추가/복사/삭제
- 운영 버전 설정
- Aidot 호환 패키지 업로드/다운로드
- WebChat 접속 주소 확인

### 5.3 팀 대시보드
- 여러 작업자가 같이 만드는 상황에서 진행 상태를 확인하는 화면
- 검토 대기 / 승인 / 차단 / 병목 / 최근 수정 / 담당자별 작업량 확인

## 6. Aidot 호환 확인 포인트
- CGA와 Aidot는 봇 단위로 100% 호환되어야 합니다.
- 확인해야 할 항목:
  - 봇 다운로드 가능
  - 봇 업로드 가능
  - 버전 관리 가능
  - WebChat 접속 가능

## 7. 이번 점검에서 확인한 항목
- 로그인 후 기본 진입 화면: `봇 작업공간`
- 시스템 관리자/일반 사용자 기준 그룹-봇 매칭 보정
- `봇 작업공간` 봇 목록 표시
- `봇 관리` 버전 추가
- `팀 대시보드` 승인 처리
- 상단 `저장` 버튼 동작
- `배포` 버튼은 운영 화면 외 숨김

## 8. 아직 직접 끝까지 검증하지 않은 항목
- 실제 파일을 선택하는 `봇 업로드`
- 실제 다운로드 파일 내용을 Aidot에 재투입하는 왕복 검증
- WebChat 실대화 연결 검증

위 3개는 화면/버튼/주소는 확인했지만, 실제 외부 파일 왕복과 실채널 연결까지는 이 문서 작성 시점에 별도 실데이터 검증을 끝내지 않았습니다.
